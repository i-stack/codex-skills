# Checkpoint Persist 详规

本文件是 [SKILL.md](../SKILL.md) 内 `CP-NNN` 规则的真值细则。落盘动作是纯文件写入，不依赖任何 CLI / 数据库 / embedding；唯一要求是路径可预测，使上下文压缩后仍能按约定路径找回。

## CP-001 触发门控

**三条全满足才落盘**，缺一即跳过：

1. **任务非平凡**：构建 / 新增功能、修改 / 重构 / 修复、方案设计 / 架构决策、迁移 / 升级、代码审查（review-only 与 review-and-fix 均含）、排障 / 根因分析。定义复用 historical-recall `HR-001`，不再另行造一套，保证两门控对「非平凡」的判定一致。
2. **存在 ≥2 个需分别产出的子结论**：多个需求、多个模块、多个决策点、多个待修点等「一批要分别分析 / 决策的对象」。
3. **子结论需跨轮存活**：后面的分析要引用前面的结论；若每个子结论彼此独立、产出即消费，不落盘。

**跳过**：trivial 任务、单轮即可完成、单点子结论、事实查询 / 翻译 / 简单解释 / typo / 格式化 / 小命令 / 纯闲聊。

> 与「盘问」的关系：本门控绑定**任务形态**（是否长流程 + 多子项 + 跨轮存活），不绑定是否进入 plan-grill 盘问。盘问场景中「多决策点」命中时同样落盘；「批量分析多个需求」这类非盘问场景命中时也落盘。是否盘问不构成落盘条件。

## CP-002 落盘对象与粒度

- **只落「结论 + 关键决策 + 未决问题」**，不落对话过程、不落思考流、不落中间推演草稿。
- **最小单元 = 单个子结论**：一条需求 / 一个模块 / 一个决策点 / 一个待修点，各占一个条目。
- 每条结论必须自包含：脱离上下文读它也能知道「这是什么、结论是什么、还有什么没定」，否则压缩后找回也无法复用。

## CP-003 落盘时机

- **每产出一个子结论立即追加写盘**，禁止攒批到任务末尾一次性写。
- 当感知到上下文即将压缩 / 超窗（系统提示压缩、或 turn 数接近上限）时，**优先把当前已产出但未落盘的结论补齐落盘**，再继续。
- 落盘是轻量动作，不做重排、不做全量重写；追加式更新即可。

## CP-004 落盘位置与格式

- **路径约定**：`<工作区根>/.plan-reviews/checkpoint/<task-slug>/CHECKPOINT.md`。
  - `<工作区根>` = 当前项目 / 工作区绝对路径根（与 `.plan-reviews/` 同根）。
  - `<task-slug>` = 任务主题的短横线命名（如 `login-rate-limit`、`multi-requirement-analysis`），语义化、可读。
  - 落点选 `.plan-reviews/checkpoint/`：与历史知识库同根，`plan-reviews` 的 `sync` 会把每个含 `CHECKPOINT.md` 的任务子目录识别为 `kind=checkpoint` 并索引，使 `historical-recall` 的 `recall` 能语义召回中间结论——超窗后既可按固定路径找回，也可靠语义召回兜底。
  - 中间态与成品的区分：checkpoint 以独立 `kind=checkpoint` 进入索引，召回结果标注 `[进行中 checkpoint]`；`merge`（新陈代谢合并）明确排除 checkpoint，进行中中间态不会被固化进 `MERGED-KNOWLEDGE.md`。
- **文件结构模板**（统一，便于压缩后按约定路径找回）：

  ```markdown
  # Checkpoint: <task 主题>

  - 状态：进行中
  - 更新时间：<ISO 时间戳>

  ## 任务摘要
  <一句话任务目标>

  ## 已产出结论

  ### 1. <子结论标题>
  - 结论：<...>
  - 关键决策：<...>
  - 未决问题：<无 或 具体问题>

  ### 2. <子结论标题>
  - 结论：<...>
  - 关键决策：<...>
  - 未决问题：<...>

  ## 下一步
  <待分析子项清单，按序>
  ```

## CP-005 恢复与生命周期

- **恢复**：新轮次开始、动手前，若 `<工作区根>/.plan-reviews/checkpoint/` 存在「进行中」的 checkpoint 目录，先读取恢复上下文，再继续任务；不得忽略已有 checkpoint 从头重做。
  - 若忘记 task-slug，列出 checkpoint 目录，按修改时间取最近一个「进行中」子目录的 `CHECKPOINT.md` 恢复。
- **生命周期**：
  - 任务完成、结论已写入成品产出（PLAN.md / 代码 / 审查结论等）后，删除对应 checkpoint 目录，避免残留误导下一轮恢复与召回。
  - 同一工作区同一任务重复进入时，续写同一 `<task-slug>/CHECKPOINT.md`，不另起新目录。
- **best-effort 失败策略**：目录创建失败、写盘失败均不阻断主任务（动作已 `|| true` 兜底）；但须在产出文档的「残留风险」中声明「checkpoint 未落盘，超窗后该结论可能丢失」。

## 与既有 skill 的衔接

- `historical-recall`：动手前召回历史线索（读）；本 skill 动手后边做边落盘（写）。触发门控复用同一套「非平凡」定义，但两者独立触发、互不依赖。
- `plan-grill`：PG-004 的「盘问达成共识后写 PLAN.md」是**成品一次性写盘**；本 skill 是**过程中间态增量写盘**。两者落盘位置不同（PLAN.md 在 `.plan-reviews/<date-slug>/`，checkpoint 在 `.plan-reviews/checkpoint/<task-slug>/`），不冲突、不重复。
- `engineering-discipline`：GR-008 要求声明「已覆盖 / 未覆盖 / 残留风险」；checkpoint 落盘失败须并入「残留风险」声明。
